## 0. 目标与约束

**目标**：让项目从「功能齐全但观感单薄」提升到「演示、软著材料、答辩都站得住」。

**约束**（来自仓库已有规则，不可违反）：

1. **不新增、删减或重定义 PRD 业务需求**（TASKS 使用约定）。视觉和交互优化不算业务变更；新增或变更业务能力需先记录冲突点。
2. **视觉方向以 UI_DESIGN 1.1 为准**：方向 B「刻度」已由产品负责人确认，禁止渐变和重阴影。若要改方向，需重新确认。
3. **软著材料与实际功能保持一致**：每完成一项，同步截图、说明书、源程序鉴别材料和 TESTING 记录。
4. **真实临床边界不变**：指导内容继续标注 DEMO-未审核；AI 不做诊断或剂量建议。

### 方案 A：数据可视化

**范围**

- **A1 统计页热力图**：患者 × 日期的覆盖矩阵，沿用 UI_DESIGN 的「刻度」语言（实心格 = 已登记，空心格 = 未发现登记，虚线格 = 未到时点）。
- **A2 缺失分布**：按时段（早 / 晚）统计缺失次数；来源占比用条形图。
- **A3 趋势图表化**：引入图表库替换手写 SVG，配色取 `theme.ts` 已有变量。图表库候选见问题 Q4 之后的技术选型（ECharts 或 @ant-design/charts，需确认）。
- **A4 工作台改版**：由「数字卡 + 列表」改为「今日处理清单」：按缺失程度排序的患者卡、今日时点完成率、到期随访。

**不做**

- 不新增业务指标，不改变覆盖率口径（UX_DESIGN §4）。
- 不做可配置仪表盘，不做导出功能（导出属于 P1 且未被要求）。

**涉及文件**

- 前端：`StatsPage.tsx`、`WorkbenchPage.tsx`、`theme.ts`、`package.json`
- 后端：热力图需要「患者 × 日期」矩阵数据。现有 `/stats/overview` 与 `/stats/trend` 不一定覆盖，**可能需要新增接口**，若新增则同步更新 `API_SPEC.md`。

**验收**

- 演示数据下 P-001 林女士的覆盖率仍为 71.4%（T06 不回退）。
- 热力图与统计明细数字一致（抽样核对）。
- 工作台截图与原截图对比，视觉层级有明显变化。

---

### 方案 B：患者端装置图示

**范围**

- **B1 分步线稿**：每个型号 4–6 步的 SVG 线稿，当前步骤高亮，覆盖 pMDI / DPI / SMI 三类。
- **B2 常见错误图标**：对应 `error_notes`，每条错误配一个简单标记。
- **B3 自检联动**：P03 自检页每一步旁边显示对应图示。

**不做**

- 不做动画（PRD 1.3 将「App 界面动效」列为 P1，本轮不做）。
- 不做真实照片或视频（需要素材版权和临床审核，超出本轮范围）。

**实现的关键决策（待定）**

- **图示与步骤的绑定方式**：
  - 方案 B-i：图示作为前端静态资源，按 `device_model` 的编码映射。优点是不改数据库；缺点是指导内容与图示分离，后续改步骤时容易错位。
  - 方案 B-ii：在 `guide_steps` 增加 `image_key` 字段。优点是绑定可靠；缺点是需要数据库迁移，并同步更新 `DATABASE_DESIGN.md`。
  - **建议 B-i**，本轮演示够用；正式化时再迁移到 B-ii。

**验收**

- 三个型号各有完整图示，步骤与文字一一对应。
- 所有图示和文字保留「DEMO-未审核」标注，不宣称为临床素材。
- P03 自检流程可走通（`smoke_s3` 通过）。

**风险**

- 线稿必须与装置厂家说明书的操作顺序一致。当前没有临床审核，图示也要标注未审核，否则会造成误导。

### 方案 C：AI 问答方向

三选一，需要你决定（见问题 Q3）。

| 选项 | 做法 | 工作量 | 代价 |
|---|---|---|---|
| **C1 诚实化（建议）** | 保留检索式问答，界面文案统一为「型号资料问答」；`llm_*` 配置明确标注为「未启用」；删除两个分支重复的代码 | 0.5–1 天 | 说明书基本不用改 |
| C2 接入真实 LLM | 实现 `_llm_answer`，提示词约束只能基于命中片段；引用仍由服务端组装；失败回落到抽取式回答；越界与敏感拦截保留 | 约 2 天 | 需要 API key 和供应商；需更新说明书「外部服务」条款（`软件说明书.md:387`），并评估问答内容外发的合规性 |
| C3 不动 | 保持现状 | 0 | 代码中的占位分支仍在，演示时若被追问可能说不清 |

**验收（C1 与 C2 共用）**

- 越界样本（剂量、诊断、急症）全部拦截，`smoke_ai_samples` 通过。
- 跨型号不引用（T12）、AI 故障回退（T14）不回退。
- 若选 C2，额外验证：LLM 不可用时回落正常，且不泄露 key。

### 方案 D：工程可信度

**范围**

- **D1 后端**：把核心 smoke 断言迁移为 pytest 用例，优先覆盖 `task_service`、`rag/service`、`stats` 三个模块；引入 `pytest-cov`。目标分阶段：先到 60%，再到 80%。
- **D2 前端**：引入 Vitest，测纯函数（覆盖率计算、时点状态判断、日期处理）。组件测试按需补充。
- **D3 验收脚本收口**：`run_acceptance.py` 改为调用 pytest，保持「一键复跑」的能力。

**不做**

- 不搭建 CI 平台（仓库无远端，属于另一项决定）。
- 不追求全量 E2E；Playwright 截图脚本保留作为证据工具即可。

**验收**

- `pytest` 一条命令通过，并输出覆盖率报告。
- 覆盖率报告写入 `docs/TESTING.md`，数字如实记录，不做美化。
