## 3. 方案 C：AI 问答（真实接入）

### C-0 前提（需要你提供）

- **供应商与协议**：你的 key 是哪家的？常见的是 OpenAI 兼容接口（`chat/completions`），Anthropic 的 Messages 接口格式不同，需要单独适配。
- **key 放置方式**：请直接写入 `backend/.env` 的 `LLM_API_KEY`（该文件已被 `.gitignore` 忽略），**不要粘贴到对话里**。如果已经粘贴过，建议在供应商后台轮换。
- 配置项已存在：`llm_api_key`、`llm_base_url`、`llm_model`、`llm_timeout_seconds`（`config.py:22-25`）。

### C-1 清理占位（不依赖 key，可先做）

- `rag/service.py:145-148` 两个分支都调用 `_extractive_answer`，合并为一个显式的分支选择。
- 无 key 时保持现有行为，回答标注「未启用大模型，基于已审核片段的抽取式回答」。

### C-2 LLM 调用（TDD）

- **实现**：`_llm_answer(question, hits)`，用标准库 `urllib` 发起请求，不新增依赖。
- **提示词约束**：只能依据给定片段回答；片段外的内容不得补充；涉及剂量调整、诊断、急症时必须拒答并引导就医。
- **外发内容最小化**：请求体只含 **问题文本 + 命中片段**。不含 `patient_id`、姓名、患者编号、计划信息。
- **敏感与越界拦截必须在调用 LLM 之前完成**（当前 `ask()` 步骤 1、2 已是这个顺序）。这是为了保证被拦截的问题永远不会被发到外部。
- **输出后检**：对模型回答再跑一次越界关键词检查，命中则替换为拒答文案。
- **引用仍由服务端组装**（`ask()` 步骤 5），不采信模型自报的出处。
- **失败处理**：超时或报错仍抛异常，由 API 层返回 503 `LLM_UNAVAILABLE`（现有逻辑）。**不静默回落**到抽取式回答，因为 T14 要求明确提示 AI 故障。

### C-3 测试

- 用 monkeypatch 替换 LLM 调用，覆盖：
  - 正常回答，引用为服务端组装的片段。
  - 超时 → 503，核心业务接口不受影响。
  - 越界样本（剂量、诊断、急症）→ 拒答，**且 LLM 调用次数为 0**。
  - 敏感样本（手机号、身份证、姓名自述）→ 拒答，**且 LLM 调用次数为 0**。
  - 跨型号不引用（T12）。
  - 请求体中不含 `patient_id` 与姓名。
- 真实 key 只跑一次手动冒烟，结果记入 TESTING，key 不进入仓库或文档。

### C-4 前端

- P05 AI 助手页的状态文案保持不变，已有「已回答（基于已审核资料）」等标签。
- 增加「回答由外部模型生成，内容仅供参考，以医护说明为准」的提示。

### C-5 说明书与合规

- 更新 `软件说明书.md` §5.3.5（AI 指导助手）与「外部服务」条款（当前为「问答请求不携带患者身份与诊疗信息」）。
- 新条款应写明：问题文本与已审核资料片段会发送至外部模型服务（供应商名称），**不发送**姓名、手机号、患者编号。
- 说明书内容须与代码一致，这是 PRD 1.5 的要求。
- PRD 是否需要补充版本记录，待你确认（见 §6）。
