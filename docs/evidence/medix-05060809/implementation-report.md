## 落地

- `/plans`、`/stats`、`/followups` 使用已有 `WebLayout variant="medix"`。`/admin`、`/patients/:id` 仍是 Comfort，截图 `04-detail-still-comfort.png`。
- 计划阶段：`derivePlanPhase`。未来 `ends_at` 仍是生效中；`now === ends_at` 为已结束。界面写「已结束」，不把届满写成已关闭。
- 开始日是上海零点，结束日含当天并转成次日零点。同日是 24 小时区间。
- 统计窗口默认是上海昨日往前的完整 7 日。本机上海日期已是 2026-11-10，所以界面是 11-03—11-09，请求 `to=2026-11-10`。这不是把图里的 11-02—11-08 写死。
- 团队覆盖率用 overview 的合计，不平均患者百分比。mock 里 10/10 与 10/90 显示为 20%，两行仍是 100% 和 11.1%。N=0 显示 —。
- 超过 92 日时页面写出「区间最多 92 日」，并且不再增加统计请求。
- 患者报告页签还在：逐日覆盖、未发现登记、登记来源、随访摘要、重复登记。07 的独立精修没有做。
- 随访待核查标题数字来自 `total`。51 条时能请求 `page=2`。切换任务前若有未保存内容会确认，确认后不残留反馈。没有关联任务时不能勾关闭。
- 处理任务弹窗：`MISSED_MEDICATION` 写「连续3个到期时点未发现登记」，其他类型写「待核查任务」。空白说明不发请求。成功请求 `close_task: true`，且只有一条 POST。工作台和随访中心用同一个组件。
- 头像仍是中性占位。生产数据没有头像字段，没有给患者分配演示脸。
