## 10 补登

`MedicationBackfillModal` 仍是 02 和 04 的同一个组件。

- 计划走 `include_history` 分页；时点单独请求。时点 500 显示加载失败，确认按钮不可用，不显示「暂无计划」。
- 已登记、未到时点禁选。可补登时点带出可修改的实际时间。
- 提交的 `plan_id` 来自所选时点。按需 `slot_id` 为 null。
- 实际时间用选择器上的墙钟加上 `+08:00`。晚于现在的时间不提交。

浏览器里用拦截数据打开了工作台补登，看到已登记和未到时点。没有选时点时不会发登记请求。04 入口已接上同一弹窗，这次没有再单独截患者详情。

## 管理端 11–15

`/admin` 使用已有 medix 外壳。侧栏是装置型号、指导版本、账号管理、知识内容、审计日志。地址是 `?tab=model|guide|user|kb|audit`。未知值回到 model。管理员顶栏是「内容与账号管理」，没有患者搜索。

每个视图自己请求。型号目录按页读完，供指导和知识显示名称。读不完就显示「型号信息不可用」，不用 UUID 冒充名称。

- 11：服务端分页，类别是中性标签。没有编辑或删除按钮。
- 12：步骤去空行后连续编号。版本冲突留在版本字段。审核前能看步骤。发布前点名标题和版本。已发布只有查看。
- 13：空密码不提交空字符串。响应里的临时密码只在结果弹窗展示一次，关闭即清。显式密码且响应为 null 时只提示账号已创建。停用文案是「停用后该账号无法继续访问」。当前账号停用后退出。界面拒绝停用唯一的启用管理员；后端没有这条保护。
- 14：正文按空行分块，片段数取 `chunks.length`，缺字段显示数据异常。详情按文档 id 重新获取。不提交 `guide_id`。
- 15：只读 `GET /api/admin/audit-logs`。区间没读全、分页顺序不稳或请求失败时不画全量柱图，已读记录单独标出。账号启停接口没有审计，图上不出现「停用账号」。
