# APP 第一批视觉稿 · 方案二

日期：2026-11-10。状态：独立静态视觉复验通过，待用户视觉确认。

## 本轮范围

生成 01 登录、02 首次改密、03 今日、04 型号指导、05 操作自检，共五张独立图片。修改页面信息组织，不修改产品代码。其余两个页面与三个展开状态留到下一批。

## 验收规则

1. 沿用已批准的 Medix Light 网页视觉：浅灰底、白色内容面、紫色主操作，蓝色图表、青绿色完成状态。禁止整页紫色、渐变大块、厚重阴影和嵌套卡片。
2. 按 390 × 844 逻辑视口设计，仅 APP 内容；不画手机外框、系统状态栏、浏览器栏。边距约 20–24，正文约 16，标题约 22，必要次级文字不小于 14，主要操作高度至少 48。
3. 删除患者编号、诊断占位、重复标题、解释性尾巴、常驻免责段落。账号标签、密码限制、日期、步骤进度和登记状态属于操作必需信息，保留。
4. 01 只保留品牌、患者登录、账号、密码、登录。02 保留原密码、新密码、确认新密码；按钮准确写“修改并重新登录”。不得增加不存在的注册、短信、社交登录入口。
5. 03 用真实人物风格头像，禁止名字前的装饰色点。下一次待登记突出；统计准确称“登记”。本稿为 2026-11-10 21:10 的示例：09:00 已登记，21:00 待登记，今日 1/2；近七个完整日为 11/03–11/09，每日登记数 2、2、1、2、2、2、1，总计 12/14。不得写实际服药依从性。
6. 03 不删除原有提醒与学习入口的能力：复训、随访、指导、自检、AI 助手均要有可理解的入口或位置；压缩文案不等于删掉业务任务。
7. 04 与 05 一屏一步，同一装置、同一步插图一致；步骤为 1/6，标题“检查吸嘴”，正文“取下吸嘴盖，检查有无异物。”。图片只表达拆下盖帽与检查入口，不生成额外用药剂量或诊疗建议。素材为设计示意，落地时替换为经审核的型号素材。
8. 04 保留今日/指导/记录底栏。上一步在第一步禁用；下一步为主操作，末步改为开始自检。05 保留返回和历史入口，不画一级底栏；选择为完成/有困难/未完成，本稿选中“完成”，保留改变选项能力；末步才提交，未选项不得自动当作未完成提交。
9. 固定操作与底栏必须各占空间，不覆盖正文；无文字溢出、裁切、悬空不明按钮；操作文字与状态不能只靠颜色区分。
10. 独立子 Agent 必须直接查看五张最终图并逐张给结论。有 P0/P1 问题先修；静态图通过不等于代码、键盘、触控或用户视觉签字通过。

## 本轮保留与删减

- 保留：账号与步骤操作要求、登记状态和计数、复训与随访提醒、三个学习入口、返回与历史。
- 删除：患者编号、重复“下一步/时点”说明、长期显示的免责声明、DEMO 与版本占位文案、图中重复步骤编号。
- 迁移：型号与审核版本在产品资料中管理；必要的设备操作警示在对应步骤出现，不重复放在每个页面底部。
