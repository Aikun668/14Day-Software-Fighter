# 13 账号管理

参考：[13](references/13-admin-accounts.png)。源图逐张批准记录未找到，留存为布局参考；当前文字规范依据已确认公共风格与继续交付授权冻结。入口/admin?tab=user，API backend/app/api/admin_users.py。

## 构图

标题“账号管理”+“新建账号”。白表五列：账号 / 角色 / 状态 / 需改密 / 操作，建议32/16/16/16/20%。账号单行真实account，长值换行或展开；这是必要登录标识，不属于可删除的患者编号。可用头像规则与00相同，真实用户无头像时中性图标，不按角色随机配脸。

角色普通文字，状态启用浅绿/停用中性灰，需改密是/否。停用使用小型珊瑚红描边或文字按钮，启用普通灰按钮；不整行红底。破坏性文字用可读深色（建议#B44545），不用浅红字牺牲对比。没有账号下admin/角色等重复副标题，没有常驻停用说明。

## 读取与创建

GET /api/admin/users?page=…&page_size=20，支持role/status过滤；不依赖客户端首100筛全库。PATIENT可在表里查看/启停，但新建接口只允许CLINICIAN和ADMIN。

新建弹窗32rem：账号必填2–80字符、角色必选（医护默认/管理员）、初始密码选填。密码用Input.Password和autoComplete=new-password，非空至少8字符。空字符串转null或省略，不发送''触发schema长度错误。账号trim；密码不能擅自trim或改变字符。

POST /api/admin/users {account,role,initial_password?}。409 ACCOUNT_EXISTS定位账号字段；422保留输入；不可在前端默默拼后缀创建另一个账户。成功must_change_password=true，页面需改密显示“是”，不得照图写“否”。

## 一次性临时密码

未提供密码时响应temporary_password只返回一次。成功后显示独立结果弹窗：账号、临时密码（遮掩可显隐）、复制、完成。只保存在内存；不写URL/localStorage、日志、toast或截图证据。关闭清空；不得二次创建账号以获取“丢失密码”。用户自己点击复制时才写剪贴板，并反馈成功/失败。

若显式传初始密码且响应为null，显示普通“账号已创建”，不编临时密码。不自动发消息通知任何人，不新增邮件/短信发送功能。自动生成密码后必须留到用户确认完成，不能创建成功即toast闪过丢结果。

## 启停

PATCH /api/admin/users/{id} body {status:'ACTIVE'|'DISABLED'}。只对已知状态提供反向操作；未知值显示原状态且无切换按钮，不能把所有非ACTIVE都当DISABLED。

停用先确认，标题含准确account，正文“停用后该账号无法继续访问。”不是常驻表头。停用当前登录账号时确认明确“停用当前账号将退出”，成功后清理本地登录态返回登录；若接续请求已401按统一认证逻辑处理，不继续显示成功后可用管理页面。启用也绑定稳定ID，表格排序/翻页不改变目标。

当前后端只是改status，get_current_user每次校验ACTIVE；没有清除AuthSession。不能承诺“已永久撤销所有会话”，也不能承诺重新启用一定要求重新登录。会话永久撤销和最后管理员保护未由当前API实现，列为后端边界，不在视觉任务内偷偷修改策略。

每行busy锁；取消无PATCH，成功后刷新目标页。失败保留原状态，不仅乐观翻标签；超时先GET核对目标，不自动翻转第二次。角色/患者绑定等不在该页编辑。

## 必验

2/80字符边界、8字符密码/空密码；PATIENT不可在新建选项；must_change_password按响应；临时密码不进toast/持久存储；重复创建409不重试变名；停用确认目标唯一；当前账号退出；未知status无错误按钮；51/101条可翻页；真实启停鉴权回归而非仅看标签颜色。
