# 15 审计日志：图表与事件流

目标：[最新15](references/15-audit-overview.png)。入口/admin?tab=audit。替代旧四列表格构图，但保留全部事件与原始字段的只读可达性。API backend/app/api/audit.py，仅GET /api/admin/audit-logs。

## 布局映射

标题“审计日志”，右侧日期范围；无新建/编辑/删除按钮。默认过去7个上海完整日，界面包含两端。图表区是一张横向白面，两列约3:2，中间细竖线，无内层圆角卡；小屏上下排。

左“操作趋势”+真实合计，逐日柱状图，蓝色，y轴次数且从0开始，整数刻度。最近一天可用同蓝加深，其余淡蓝；不以紫统染。右“操作类型”横条图，类别蓝/淡紫/青绿/杏及中性其他，与图例一一固定。图形高约13rem。图中42、18等仅示例。

下方独立“事件记录”白面，右侧全部类型筛选。按上海日期分组，日期标题；每行时间 / 轻色图标 / 简短动作 / 右箭头。普通行不再堆account、resource_id、detail摘要等小字。行高3.75rem，细线；动作长时换行。图标是事件类别，不是患者蓝点装饰。

点击整行/键盘Enter打开只读详情，显示完整日期时间、动作、资源类型、资源ID、actor_id（缺失—）、原detail字段；不是链接患者临床档案。详情按字段行排列，不套卡。旧表的全部信息仍可查。

## 当前接口的明确边界

接口参数只有page/page_size（最大100）、actor_id、resource_type；没有from/to、action分类或聚合接口。不得把不存在的查询参数发出后假定过滤成功。当前账号创建/启停API没有调用write_audit，前端不能从users当前状态猜出历史停用事件。

本期采用现有日志分页读取，再在前端构建声明范围内的只读图表，不新增后端API。分页策略如下：

1. 按created_at倒序请求page_size=100，从第1页开始。固定本轮查询key=(范围起止、筛选、刷新序号)，记录读取开始时间。
2. 按id去重，将created_at按Asia/Shanghai归日；取[start日零点,end次日零点)内事件。遇到整页已早于start且排序验证正常，或已读到total末尾，才判区间读取完整。遇到同时间戳边界继续取，不能用“刚读到一条旧记录”提前丢掉整页未处理数据。
3. 比较分页total、重复/排序异常与刷新后首尾边界；并发写入导致不稳定时重取一轮，仍不稳定显示“数据更新中，请刷新”。该分页接口无快照保证，界面用按需口径说明“读取截至…”，不能宣称事务一致的实时全集。
4. 单轮最多读取50页/5000条，这是客户端资源上限，不是业务总量。达上限仍未到start/末尾，或中途失败，则图表位置显示“区间数据未完整读取，请缩小日期范围”，不画部分总数为全量。已读事件可列出并明确“已加载记录”，可重试/缩小范围。禁止静默截断。
5. 取消/换日期/离开视图中止后续分页，旧结果不能覆盖；不对每个日期发一组全量请求。当前数据量若不适合这个策略，单列后端聚合需求，不交伪完整图。

所有图表、合计、事件类型筛选均从同一份完整区间数据派生。默认显示全部类型；改变类型同步过滤图表与事件流，标题标明选中类型。每日零柱只在区间读取完整后填0；空区间成功时“暂无记录”，请求失败不是零事件。

## 类型分组与未知值

显式action映射，不按字符串包含“CREATE”就算账号：

|类别|当前已核实action|颜色|
|---|---|---|
|内容审核|GUIDE_REVIEW、KNOWLEDGE_REVIEW|淡紫图形，深灰文字|
|内容发布|GUIDE_PUBLISH、KNOWLEDGE_PUBLISH|青绿|
|型号维护|DEVICE_MODEL_CREATE|杏|
|账号管理|当前未核实任何已写入action；保持0或不显示空分类|蓝|
|其他|GUIDE_CREATE、KNOWLEDGE_CREATE、PLAN_CREATE、PLAN_REVISION、MEDICATION_RECORD、MEDICATION_REVOKE、FOLLOWUP_CREATE、TASK_CREATE及未归类值|中性灰蓝|

PATIENT_ACCOUNT_BIND若出现属于临床绑定事件，保留原动作“绑定患者账号”，此版归其他，不冒充admin账号停用。未来新增账号事件必须先核实后端action再扩展显式表。未知action原样显示，不能删除、自动归入已知语义或改造成“停用账号”。

操作类型图可隐藏计数0的行，非零的其他不可丢；总合计=每日合计=分类合计=区间去重事件数。每日图计数只读实际事件，不拿当前用户/内容数量替代事件数量。图表有同数据可展开表，不能只靠hover查看数值。

## 事件详情与内容减法

默认最近4条，按需“查看全部X条”展开每批20条，X来自已完整读取并筛选后的区间记录数，非API全历史total。日期分组跨页续接，不重复/丢事件。只读原detail按结构化字段安全显示；对象/数组用可展开格式，不String(object)变[object Object]。

reason原文若乱码/问号，不猜成可读临床原因：摘要“原始内容异常”，详情保留原值。时间无法解析则标“时间异常”，不能放入某一天统计；作为数据异常处理并提示。禁止解析文本为HTML；敏感字段若意外返回应遮掩并报告，不能散播到截图。无删除/撤销审计功能。

## 必验

101条跨页、日期起止边界、同时间戳跨页、非上海电脑时区；每日/分类/列表计数相等；未知action与其他可见；实际无账号日志时账号条为0而不是图示18；5000上限/中途500/并发变化不伪全量；类别筛选同步；乱码原文可查；长detail可展开；无写入请求；真正管理员权限。
