# 07 患者报告独立规格

目标：[07图](references/07-patient-report.png)。实现位置frontend-web/src/pages/clinician/StatsPage.tsx的report页签，复用已有CoverageTrendChart/ECharts及medix组件。独立设计项不等于新建路由。

## 构图与显示层级

外壳、页首“统计与核查”、右侧日期范围/近7日与06一致；导航选中统计与核查。第二个页签“患者报告”紫色下划线选中。不要在内容区重复标题“基础管理报告”，不用一张巨型覆盖环挤占首屏。

自上而下六层，均是平面同级白面，gap1rem–1.25rem，边角.5rem，padding1.25rem；主画布#F6F6F6。以1440×1080的全页构图为参照；1440×900允许正常纵向滚动，不要求压缩所有内容进900像素。

|层|内容/尺寸约定|实现映射|
|---|---|---|
|1|约4rem高身份摘要条，左头像2.25rem+姓名选择器；右三段摘要，以细竖线隔开|患者选择ID，登记覆盖率、M/N、未发现登记数；姓名只一次。|
|2|全宽每日登记覆盖，图表内容约11rem–13rem高|蓝折线，纵轴0–100%，横轴真实日期；可聚焦信息入口。|

|4|全宽随访摘要，标题右“查看全部”|时间/反馈/措施/后续四列，默认最新3条。|

“六层”按页首页签之后的布局描述包含中间左右两个内容面：共身份、趋势、未登记、来源、随访、重复登记六个内容面，不是六张嵌套卡。空态与小屏见后文。

正文.9375rem，标题1.0625rem/500，数值可1.25rem/500；辅文不小于.8125rem。折线点值在7日等稀疏区间可标出，长区间只在tooltip显示，避免重叠。无曲线大面积紫色填充、上升箭头和重复“M=…,N=…”角标。

## 患者身份与查询状态

从06表格“查看”进入时传稳定patient_id，沿用同一区间，不因切页签重置日期。页签内选择器允许姓名/编号搜索，常态只显示姓名；同名选项才显示编号消歧。患者不在首100目录缓存时补取或用已核实overview行对象，不显示错误姓名。

未选患者时只显示选择器和“请选择患者”，没有假0摘要/示例图。选中后query key=patientId+from+to+requestSeq；选择/日期变化立即隔离旧数据。A慢B快最终只能更新B，页签隐藏后失效请求不得反写当前报告。

## 接口、时间与口径

|内容|接口/口径|
|---|---|
|摘要、缺失、来源、重复|GET /api/patients/{id}/stats?from=…&to=…|
|每日趋势|GET /api/patients/{id}/stats/trend?from=…&to=…|
|随访|GET /api/patients/{id}/followups?page=…&page_size=100，按区间过滤与分页。|

界面日期包含首尾，业务时区Asia/Shanghai。2026-11-02—11-08请求from=11-02、to=11-09，1–92日；近7日为截至上海昨日的完整七日。允许选今天，但只算已到期时点。

N=窗口内有效且已到期固定计划时点数；M=其中有ACTIVE登记的不同时点数。coverage_rate=round(M/N*100,1)，N0为null；不能平均逐日百分比，也不能把缺失时点称漏服。

每日点来自trend，summary来自stats。核对区间/时区及sum(points.N/M)与stats.N/M；不一致时重取这一对一次，持续不一致显示“数据更新中，请刷新”。不同请求缺乏原子快照，禁止拼成一份自相矛盾的报告。

N0日期点null、断线，tooltip“无到期时点”；M0且N>0真实0%。负值或M>N为数据异常，不静默裁剪。图表卸载dispose、尺寸变化resize、切回页签resize；提供可展开数据表供键盘/读屏使用。

## 未登记、来源、随访、重复的具体行为

未登记数据以stats.missing_slots为准，按scheduled_at升序。0条时“暂无未登记时点”，失败是“加载失败”，不能混同。默认最近区间中前5条，更多用“查看全部X个”展开完整日期时间；同刻多个slot保留ID分别列出，必要时补计划消歧，不按时间字符串误去重。

图中两条小杏色横条分别表示1个时点，不是状态圆点。时点很多时保留原MissingBars按日数量分布，并附可展开逐时点列表；不得每条堆一张卡。全量列表是同一白面内展开行，不另套灰底盒。

登记来源是source_breakdown按ACTIVE_EVENT_COUNTS计数；横条宽度=count/sum(source_breakdown)，数字显示事件数，不显示为覆盖率。图中患者自述10、医护观察3，共13事件，而M=12；因为一个slot有两条ACTIVE事件。合法存在sum来源>M，不能改成12“对齐摘要”。计数为0时灰空条；全0时“暂无来源记录”；未知source保留后端值作为一类。

来源标题信息入口说明“按有效登记事件计数，非去重；患者自述未由设备验证”，覆盖标题入口说明“登记覆盖不等于实际服药依从性”。支持点击/键盘展开，页面不常驻重复免责声明。

随访摘要默认周期内最新3条，时间/反馈/措施/后续；空字段—，长文两行后明确展开。措施浅青绿、后续浅杏是列类别，不推断治疗成功。按接口倒序读取直到已有4条区间记录、越过区间起点或到total；首100不够则继续，不能伪称周期无记录。“查看全部”跳/followups?patientId=当前ID，若08尚无日期筛选，不伪称跳转后已按当前报告区间筛选。

duplicate_slots非空显示独立表，按scheduled_at排序；active_event_count展示条数，不把重复数累加M。为空直接不占面板；请求失败不能错误隐藏真实核查项，显示报告区错误。列表能完整展开，多条不裁掉。

## 响应式与状态

主区不足55rem时未登记/来源上下排；<768px身份摘要换行，患者选择器独占一行，控件不少于2.5rem，表格可局部横滚。桌面侧栏/顶栏继承00；页面自身不横向溢出。图末/底部重复登记可自然向下滚动，不缩字强塞一屏。

stats、trend、followups独立loading/error，部分失败仅影响相应区域，但摘要/趋势不一致必须提示。403/404表示不可访问，不显示“暂无报告”。报告页只读，没有新增写入、导出或下载报告按钮。
