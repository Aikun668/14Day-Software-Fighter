标题“统计与核查”，右侧日期范围选择与“近7日”。下方两个页签“团队概览 / 患者报告”。默认团队概览；点表格“查看”切到该患者报告，保持区间。

团队页顶部只一行“登记覆盖率 75%   已登记 210 / 应记录 280”式摘要，数字来自接口；不做四张指标卡。保留一个可聚焦的“统计口径”入口，点击/键盘展开“基于登记记录，不等于实际服药依从性”，不在每张卡下面重复解释。

中间两块并列白面：左约 2fr 趋势，右 1fr 环图，gap 1.25rem，内边距 1.5rem，图表内容高约 15rem。主区不足 55rem 改上下排列。下方全宽患者表格独立白面，不能用一个总卡再套三个卡。

|区域|样式和内容|
|---|---|
|逐日登记覆盖率|蓝折线，无大面积紫色填充；纵轴固定 0–100%，轻水平网格，点按真实日期分布。|

不同患者的同一覆盖率条统一青绿，背景中性；不按行随机紫蓝橙。低覆盖也不自动判临床危险。比例数值用正文深色。图例、tooltip、可读数据表保证不只靠颜色。

## 数据与日期契约

业务时区 Asia/Shanghai。界面范围两端包含：选择 2026-11-02—2026-11-08，对应请求 from=2026-11-02&to=2026-11-09，后端左闭右开。近7日定义为截至上海昨日的完整七日；当上海日期为11/09，显示11/02—11/08。允许用户选含今天区间，但只统计已到期时点。每次范围 1–92 日，超限在发请求前阻止。

|对象|数据源/计算|
|---|---|
|总摘要、环图、患者表|GET /api/stats/overview?from=…&to=…，使用 total_M / total_N / coverage_rate / rows。|
|团队逐日趋势、登记明细|GET /api/stats/matrix?from=…&to=…，days 与 rows[].cells 按 day 校验匹配；逐日 sum(M) / sum(N)。|
|患者报告|GET /api/patients/{id}/stats 与 /stats/trend，带相同 from/to。|
|患者报告随访|GET /api/patients/{id}/followups?page_size=100，读取分页，在上海区间内过滤。|

N = 窗口内已到期有效固定计划时点；M = 其中有有效登记的不同 slot_id 数。不得求“患者百分比的平均值”，不得按前5行聚合。重复登记不会增加 M。

例：患者 A 为1/1、B为1/9，团队为2/10=20%，不是(100%+11.1%)/2。每日百分比先合计整数，再四舍五入至一位；展示完整整数不强制 .0。

overview 与 matrix 分别响应，必须带同一 query key（from,to,timezone）。两者都是同口径实时读取但无事务快照保证：发现 total_M/N 不一致时刷新这一对一次；仍不一致显示“数据更新中，请刷新”，不能把不一致数据拼成一张可信报告。不要靠裁剪/补零让图相等。

数据转换函数 aggregateDailyCoverage(matrix) 返回 {day,N,M,coverage_rate:number|null}[]。按 days 顺序对齐，不用图表 filtered index 反查源数组。未知/缺失 day、负值、M>N 判为数据异常；不静默 clamp。除法前判断 N。

## 图表边界与可达性

N>0 且 M=0 是真实 0%，折线落在零线；N=0 为 null，折线断开且 connectNulls=false，tooltip“无到期时点”，不能画为 0%。全周期 N=0，环图为中性空环、中心 —，没有伪造的绿色占比。

tooltip 显示日期、已登记 M / 应记录 N、登记覆盖率；不要叫“服药率”。日期轴 7 日尽量完整显示，长区间减少刻度文字但不丢点。纵轴单位 %。环图数字和图例比色块优先。

图表提供同数据的可展开“数据表”，键盘和读屏可用；不依赖只能鼠标 hover 的内容。resize 观察实际容器；从隐藏页签切回重新 resize；卸载 dispose。动画简短并响应 reduced-motion。

图中的上箭头没有同比/环比来源，删除。不能为了画平滑曲线虚构中间日期或填充缺失值。折线不作暗示超出 0–100% 的平滑过冲。

## 患者表和查询状态

沿用接口缺失数降序，N=0 垫底、同值按编号排序，不在视觉里显示编号。默认显示5行，“展开更多”每次5行；这是接口全 rows 的展示折叠，不是统计样本限制。空表仅在请求成功且 rows=[] 时显示“暂无患者”。

请求失败各块显示“加载失败 / 重试”；不把 overview=null 显示成0%。换日期立即让旧数据退出当前区间，显示骨架；失败不把旧图挂在新日期下面。患者报告请求使用 patientId+from+to+序号隔离，切换选择或离开报告时失效旧结果。

患者目录首次只有100条时，表格行“查看”仍须能从该 overview row 的 ID/姓名打开报告，不能因未在目录缓存中而消失；选择器继续分页。403/404 用权限/不可访问状态，不显示“没有数据”。

## 患者报告：保留功能，重排而非删除

本页签没有新的独立批准图，按同一系统补齐现有功能。顶部患者选择器与单行摘要；姓名只出现一次，无编号副标题。

1. 全宽逐日覆盖率蓝折线，使用患者 trend 接口，不从团队趋势裁切。
2. 下方两个同级白面：左“未发现登记时点”保留 MissingBars 与可展开完整时间列表，杏色；右“登记来源”两列表格，来源/事件数。
3. 全宽“随访摘要”，默认最近3条；“查看全部”切 /followups 并携带患者 ID，随访页读取并预选。字段为空用 —，不可编写随访结论。
4. duplicate_slots 非空才出现“重复登记”表，列为应记录时间/有效登记条数；这是核查项，不增加覆盖率。

来源统计按 ACTIVE_EVENT_COUNTS，可能大于 M，不能冒充登记时点占比。只在“登记来源”的口径弹层保留“按有效登记事件计数；患者自述未由设备验证”；页面其他位置删除重复免责声明。

随访分页：需得到周期内最新3条并确定是否还有更多。按接口倒序逐页读取，直到已有至少4条区间记录、已越过区间起点或 total 已取完；若采用固定100条上限，则必须显示“仅已加载记录”，不能宣称周期无随访。无额外后端筛选接口可假定。

2/10 加权20%；M=0与N=0区分；重复事件不增加M；1日、92日、93日；上海边界且浏览器其他时区；A慢B快最终仅B；日期变化旧数据清除；单块失败不冒充空；overview/matrix不一致可见；患者ID不在前100仍可打开；来源总数大于M正常显示；矩阵和重复核查入口仍可达。
