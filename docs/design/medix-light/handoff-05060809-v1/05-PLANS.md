# 05 用药计划

目标图：[05-plans.png](references/05-plans.png)。代码：frontend-web/src/pages/clinician/PlanEditPage.tsx。接口依据：backend/app/api/plans.py、schemas/plan.py。

## 构图与组件映射

页面标题“用药计划”，右侧患者选择器宽约 15rem。不保留“为某某编辑方案”大标题、重复患者摘要和说明段。演示标识仅在真实演示模式出现。

桌面主区两列，左 3fr、右 2fr，gap 1.25rem，align-items:start。左白面“新建计划”，右白面“历史计划”；内边距 1.5rem，不再套灰底小卡。主区不足 60rem 时上下排，表单在前。顶部选择器窄屏独占下一行。

|图中部件|实际实现|
|---|---|
|患者选择器|使用真实 patient ID；姓名展示，输入可搜姓名/编号；重名选项加编号消歧。|
|装置型号、药物名称|一列两行，控件占满；型号用接口名称，不手写选项。|
|固定 / 按需|单选组，映射 REGULAR / PRN，不写长解释。|

|每日时点|DailyTimesEditor，已选 HH:mm 为轻描边可删除项；“添加时点”打开时间选择。不是多层卡片。|
|创建计划|左对齐紫色主按钮，高 2.5rem；提交中保留宽度。|
|历史计划|药物名与状态同一行，下一行起止日期及每日时点；细线分隔条目，无编号/版本徽标/重复型号段落。|

药物名正文 .9375rem/500，状态 .8125rem；日期与时点使用 .8125rem，不用过淡灰。REGULAR 历史显示 enabled 时点，按时间升序；PRN 显示“按需”。版本与 plan_group_id 保留内部，不在普通历史列表堆叠展示。药物名长时换行，不能把状态挤出容器。

## 查询、字段和提交

初始 GET /api/patients?page_size=100、GET /api/device-models?page_size=100；翻页读取总量或在下拉滚动时继续加载，不能把首 100 个冒充全部。页面未选患者时表单禁用，历史区仅“请选择患者”。

选患者后 GET /api/patients/{id}/medication-plans?include_history=true&page_size=100。历史按后端顺序展示，首屏 5 条，“加载更多”取后续页；总数来自响应 total。

POST /api/patients/{id}/medication-plans：

|字段|规则|
|---|---|
|device_model_id|所选装置 ID，必填。|
|drug_label|trim 后非空；不替用户选择药物、剂量或治疗方案。|
|plan_type|REGULAR 或 PRN。|
|timezone|Asia/Shanghai。|
|starts_at|界面开始日的上海时间 00:00:00，序列化带 +08:00。|
|ends_at|空则 null；界面结束日表示包含该日，转次日上海时间 00:00:00 的排他边界。|
|daily_times|固定计划至少一个合法且不重复的 HH:mm；映射 {local_time, label:'时点1'…}。按需一律 []。|

日期口径是本包明确的日期型控件约定：开始日与结束日可同一天；转换后 ends_at 必须大于 starts_at。编辑器校验 00:00–23:59，不能只验证两位数字正则。无需改变后端字段。历史结束时间若恰为上海零点，显示前一日；非零点的历史记录显示真实日期时间，不把既有时间静默取整。

创建新计划是现有 POST create：产生新 plan_group_id，不自动替换旧计划。不要为贴合“历史计划”构图而自动关闭当前计划或改调用 revisions。当前页面未暴露修订操作，本批不新增修订流程。

## 计划状态

按每条计划的真实时间计算，边界为 [starts_at, ends_at)：

|条件|标签与颜色|
|---|---|
|now < starts_at|待生效，灰中性|
|starts_at <= now 且 ends_at 为空或 now < ends_at|生效中，青绿浅底深绿字|
|ends_at 非空且 now >= ends_at|已结束，杏浅底深棕字|
|非法日期或 end <= start|状态不可用，保留数据异常提示，不猜“已结束”|

图中的“已关闭”落地改“已结束”：API 没有独立关闭状态字段，不能把日期届满冒充人为关闭。页面重新获得焦点/刷新数据时重新计算 now，不能初始化时固定一次后永久不变。

## 行为和异常

切患者：受控 Select 更新 ID，清空上一个人的历史和表单、校验状态、时点；未提交内容有变动时用一次简短确认“切换患者将清空未保存内容”，取消则保持原选择。提交中禁止切换患者。请求序号确保 A 的迟到响应不覆盖 B。

切 PRN 隐藏时点，提交 []；切回 REGULAR 可恢复本次未提交的固定时点草稿，但仍校验。切患者或创建成功必须清空草稿。

提交仅一个请求在途，按钮 loading；失败保留全部输入并显示真实简短错误。成功重置表单、保留患者选择、刷新历史。成功后刷新失败只重试读取。网络结果不确定时先刷新核对，避免自动重试创建。

患者/装置加载失败分别显示重试，不变成“暂无患者/装置”。历史失败不阻止用户查看已经加载的表单，但不能显示空历史。无历史时仅“暂无计划”。不显示重复成功长说明。

## 必验

REGULAR 空/重复/非法时点不提交；PRN 不发送残留时点；结束日含当日转换正确；浏览器设为非上海时区结果仍正确；未来开始、未来结束、已结束三种状态正确；选 A 后立即选 B 不串数据；创建失败不清表单；多计划可并存，不自动关闭旧计划。
