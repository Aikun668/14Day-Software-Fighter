# 08 随访中心

目标：[用户指定彩色标签版](references/08-followups.png)。实现文件 frontend-web/src/pages/clinician/FollowupPage.tsx；接口依据 backend/app/api/followups.py、tasks.py、schemas/followup.py。

## 页面层次

顶行“随访中心”，右侧紫色“新建随访”。上下两个同级白面，间距 1.25rem、内边距 1.5rem。禁止给每条任务或记录套小卡。

上区“待核查”旁跟真实总数，表格只有患者/操作两列。患者是 2.25rem 写实头像+单行姓名；操作为灰色描边“快速处理”“填写随访”，高 2rem，触屏目标至少 2.75rem。不要显示编号、创建时间和逐条重复的触发长句；必要触发原因放 09 弹窗。

下区“随访记录”，右侧“全部患者”筛选。表头淡灰，列：时间 / 患者 / 反馈 / 措施 / 后续。桌面建议宽度 15% / 20% / 29% / 18% / 18%，实际允许随长内容调整。行最小 3.5rem，超过一行时自然增高。

措施字段采用浅青绿底+深绿字，后续采用浅杏底+深棕字，沿用批准图轻快感。这些是文字类别标签，不是“已成功/失败”的状态判断。反馈普通正文。空字段显示 —；不要生成“无反馈记录”等一串小字。长文字默认最多两行，明确“展开”按钮展示该条完整原文，键盘可操作；不能永久截断临床记录或把整段硬塞进一颗小胶囊。

页面宽度不足时操作换行；表格只在自身容器横滚，最小宽约 48rem，患者和时间可见，不让整页溢出。表单移动端一列。页面滚动正常，不固定为截图高度。

## 数据读取与分页

患者选择器 GET /api/patients?page_size=100，按 total 延续分页。任务 GET /api/tasks?status=OPEN&page_size=50；本批保留当前 OPEN 队列口径，不悄悄增加 IN_PROGRESS 流程。UI 总数读取 total，不是首50条长度。

记录：全部患者用 GET /api/followups?page_size=50；选定患者用 GET /api/patients/{id}/followups?page_size=50。排序由接口 followed_at 倒序提供。后续查询均使用 page/page_size，不把本地 slice 当服务器分页。

任务和记录各默认5条，底部“加载更多”先显示缓存中下一批5条，缓存不足再请求下一页；达到 total 后不再提示剩余。图中的9和4行是样例，不改变实际分页规则。两区独立加载/失败/展开状态；改变患者筛选只重置记录列表，不清任务队列。

从患者报告传入患者 ID（建议 /followups?patientId=…）时预选历史筛选；ID 不在缓存中补取可访问患者，不自动打开新建表单。筛选结果异步返回时核对当前 ID，旧响应不得覆盖。

## 三个入口的不同职责

|入口|行为|
|---|---|
|新建随访|打开页面内完整表单；无患者和任务预选，时间为当前上海时间。|
|任务行“填写随访”|打开同一完整表单，预选该任务患者与 task_id；记录筛选同步该患者。|
|任务行“快速处理”|打开共享 09 弹窗；简短处理说明，成功后保存随访并关闭任务。|

完整表单保持现有页面内方式：放标题下方、两个列表前，独立白面，不塞入任务卡内部。打开后滚动到表单并聚焦患者或反馈；收起后焦点回到触发按钮。不另外造一个和 09 近似的完整表单弹窗。

## 完整随访表单

|控件|后端字段与规则|
|---|---|
|患者（必填）|patient_id。使用受控 ID。|
|关联任务（可空）|task_id；下拉只含当前患者可处理任务，选项使用简短类型/时间消歧，不显示全长 UUID。|
|随访时间（必填）|followed_at，日期时间控件，上海时间展示与带时区序列化。|
|反馈 / 措施 / 后续|feedback / action_taken / next_plan；可选多行文本，保留现有非必填契约，不臆造200字上限。|
|同时关闭关联任务|close_task，默认 false；无 task_id 时禁用并置 false。|
|安排操作复训提醒|create_retraining_reminder，默认 false。|
|保存 / 取消|紫主按钮与灰次按钮；只一次提交在途。|

POST /api/followups 使用以上字段。前端 task_id 必须属于 patient_id，即使 close_task=false 也要验证：当前后端只在关闭分支检查任务归属，前端不能假定后端已兜底所有组合。发现缓存任务无法核实归属时清除关联，不能带猜测 ID 提交。此处不扩大本批为后端安全重构。

重新打开表单必须先 resetFields，再写入新上下文；不能让上一位患者的反馈、checkbox 留到下一位。表单中切患者时清空 task_id 和 close_task，重载任务选项；已有输入的整体上下文更换先简短确认，取消则保持原上下文。取消表单重置全部字段和 formPatient，但保留记录筛选。

完整表单与快速弹窗避免同时处于可编辑状态：已有未保存表单时，启动另一上下文先确认丢弃；不需要每次无改动打开都弹确认。提交期间禁用会切换上下文的动作。

## 保存和错误

API 201 后关闭/重置表单，刷新 OPEN 队列、团队记录和当前患者记录。取消不发请求；失败保留输入和上下文。任务已关闭409时保留文本、刷新队列并提示“任务已关闭”，不自动再创建一条不关联随访。422关联不匹配指向任务字段；403/404显示不可访问并阻止继续保存。

快速处理成功执行相同刷新集合，详见 [09](09-TASK-CLOSE.md)。保存成功但列表刷新失败应分开提示，重试只读请求。网络超时结果未知时先刷新核对，不自动重发。

各区加载中用骨架，失败“加载失败 / 重试”，成功空才“暂无待核查任务”或“暂无随访记录”。患者信息没有加载成功时不拿 raw UUID 充姓名；保留重试并禁用依赖身份的操作。

## 必验

先编辑A再打开B不残留文字；关联任务始终属于当前患者；无任务不能勾关闭；反馈等空值仍遵循API契约；五列长文可展开；记录筛选不影响任务；分页超过50仍可达；快速处理后两列表更新；保存失败不丢输入；带患者链接进入预选正确；生产无照片时不伪造人像。
